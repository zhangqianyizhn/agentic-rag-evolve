# ADR-0001：采用领域原生、证据驱动的闭环

- 状态：Accepted
- 日期：2026-09-06

## 背景

HarnessFix 展示了“轨迹标准化—失败归因—修复—验证”的有效组织方式，但其 agent 分层、缺陷类型和修复算子主要为通用工具 agent 与特定 benchmark 预设。DeepRead 的关键状态则是文档选择、目录加载、分片候选、section read、证据覆盖与答案合成。

## 决策

保留 HarnessFix 的闭环与审计思想，但重新定义面向 RAG 的 QueryTrace。诊断以开放因果描述为主，固定字段仅约束证据、干预节点、修改范围和验证方法；修复不依赖封闭 operator registry。所有候选通过同数据集留出和跨数据集回归门禁。

## 影响

前期需要先建设可靠的产物适配与轨迹编译，不能直接复用 HarnessFix 的诊断 prompt；相应地，系统可以表达尚未预见的新缺陷与新修复方式，并更适合研究跨数据集泛化。
