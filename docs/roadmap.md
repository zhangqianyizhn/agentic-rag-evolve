# 分阶段实施路线

每个里程碑只引入一个可独立检查的能力；完成条件是可运行的测试和一个小型真实产物 smoke test，而不是仅有接口占位。

## M1：实验登记与产物读取

- 定义 `ExperimentManifest`、生成/评测记录的版本化 schema；
- 读取 ruc-ov 单次及分片合并实验，校验 ID、数量和文件哈希；
- 输出数据质量报告，不调用 LLM。

验收：对 FinanceBench、Locomo、SyllabusQA 各一个既有实验稳定解析；错误路径、截断 JSON、重复 query 有明确错误。

## M2：DeepRead QueryTrace

- 编译 `deepread_run.log`，处理并发乱序、重试与旧日志；
- 将轨迹与 `generated_answers`/eval/corpus 坐标对齐；
- 提供单问题的紧凑可读视图和机器可读 JSON。

验收：能从问题追到每次工具调用、候选分片、read 内容和最终答案；所有派生字段可追溯到 source ref。

## M3：确定性信号与 bad-case 报告

- 实现 evidence-to-corpus 匹配与覆盖率；
- 区分“未召回、召回未读、已读未正确回答、执行失败、标注/评测可疑”；
- 生成数据集与 cohort 统计。

验收：抽样人工核查，并记录各信号的准确率/不确定样本，不把启发式结果当根因。

## M4：证据锚定诊断 agent

- 设计诊断输入裁剪和按需查看工具；
- 输出自由根因、最早可干预节点、反事实、代码范围和判别实验；
- 加入 schema、引用存在性、自相矛盾与多次诊断一致性检查。

验收：在冻结样本上与人工诊断比较“节点、原因、证据、修改范围”，而非只比较标签字符串。

## M5：归并与改进假设

- 对诊断做语义归并和 cohort 对照；
- 估计覆盖样本、潜在收益、回退风险与数据集特异性；
- 产出有优先级的、可证伪的 hypothesis spec。

验收：每个假设包含支持例、反例、最小消融和明确接受条件。

## M6：隔离修复

- 创建目标 revision 的 worktree/实验分支；
- 按允许范围生成补丁，执行 diff/测试/配置检查；
- 保存 patch manifest，不自动合并到 ruc-ov 主分支。

验收：失败可回滚、修改可复现，且补丁以机制为单位而不是混合多个不可归因变化。

## M7：分级验证与选择

- bad case 重放、同数据集留出、多数据集回归、完整评测；
- 配对比较 Accuracy/Recall/成本/稳定性；
- 支持接受、拒绝、保留为 dataset-specific 三种结果。

验收：门禁规则预先写入 manifest；验证数据不泄漏到修改提示。

## M8：闭环与进化记忆

- 串联为可恢复状态机，加入预算与人工审批点；
- 检索过去成功/失败假设，检测重复尝试；
- 支持多候选竞争与跨数据集迁移实验。

验收：从一个冻结 baseline 自动运行一轮，并完整复现实验谱系与决策。

## 推荐的首个实现切片

下一次只实现 M1。先选三个现有结果目录作为 fixture 来源，脱敏并裁剪出最小样本；不急于实现 LLM 诊断。M1 稳定后，M2 才有可靠输入契约。
